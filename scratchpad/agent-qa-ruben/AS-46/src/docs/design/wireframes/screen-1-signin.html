S1-ERROR-SYSTEM Error — system Two distinct triggers, one ledger row — both illustrated below

Sign-up / sign-in — account errors

Sign-up: email already registered

An account already exists for ada@example.com. Sign in instead, or use a different email.

Sign-in: no matching account, or wrong password

Email or password is incorrect.

Deliberately the same message for "no account with this email" and "wrong password" — naming which one it was would confirm to an attacker which emails have accounts. There is no password-reset link to offer instead (C-09 is OUT of v1 — no affordance is shown, disabled or otherwise; a dead control is a design lie).

S1-DENIED-AUTHENTICATED Permission-denied / gated An already-signed-in freelancer requests this screen

No form renders

This state has no visible sign-in form. A signed-in freelancer who requests /signin is redirected immediately to the Dashboard (Screen 3) — the redirect happens before any of the markup above is served. Recorded here so "what happens if a signed-in user hits /signin" is a decision, not a gap a developer has to guess at.

S1-ABANDON Abandonment Freelancer starts either mode, navigates away before submitting

Nothing is lost

No server-side state is created until a submit succeeds, so leaving mid-form costs nothing. Returning to /signin renders a blank S1-DEFAULT-SIGNIN or S1-DEFAULT-SIGNUP again, never a resumed draft — there is no draft concept on this screen.
