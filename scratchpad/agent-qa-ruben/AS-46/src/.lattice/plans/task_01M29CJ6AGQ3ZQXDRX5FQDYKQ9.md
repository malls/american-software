# AS-121: Chat tooling: compose-run.mjs does not tear down on SIGINT/SIGTERM — an interrupted counted run leaves its image (and, off the pinned compose, its network) behind

Found in the AS-106 review (qa-priya, 2026-09-11). The AS-106 plan §2(b)4 says the always-down teardown runs 'on SIGINT/SIGTERM (the trap … EXIT of the shell recipe, in node)', and §5 treats T5c (exec stub throws) as the proxy for that path. It is not one: bin/compose-run.mjs registers no signal handler and drives docker with spawnSync, so a signal to the node process ends it before any JS can run. Observed for real (scratchpad/agent-qa-priya/AS-106/sig.mjs): SIGTERM to the script mid-container -> node exits with signal=SIGTERM, prints nothing (no receipt), the compose child runs on and --rm removes only the container; asc-review-as106-sigterm_default and asc-review-as106-sigterm-test:latest survived until a hand 'down -v --rmi local --remove-orphans'. With the AS-106 network_mode: none pin the chat suite leaks only its image this way; any other compose dir (T11's shape) leaks a network too. This is the tick-timeout / harness-termination case in real operation. Fix shape (implementer's call): ignore SIGINT/SIGTERM in the parent for the duration of the run (process.on(sig, noop) before spawnSync, remove after) so the child's termination surfaces as a non-zero status and the existing always-down path runs; add a real-signal test (opt-in, AS106_REAL style) whose falsifier is 'remove the handler -> the network survives'. Not blocking AS-106: AC-5 names exit 0 / exit 1 / throw and all three hold; the plan itself de-scoped a real-signal test.
