FINDINGS OUTSIDE THE CRITERIA LIST
1. The wedge is strictly file-local to the two server-owning tests, and the plan's §2 parked item is the real root cause. The process-level hang needs BOTH a live listening server AND the ref'd heartbeat setInterval (server.js:613 — the only server interval not unref()'d; loopPoll/lanesPoll/eventsPoll are). §3B is what actually terminates the run; §3A alone does not (AC-3b). That means any FUTURE test in any file that owns a server and closes it inline without an after-hook re-opens exactly this hole — the fix is per-test, not structural. I did not find a third instance in stream.test.js (so per §8 I am not filing the audit follow-up myself), but the audit of other test files for server-owning tests without t.after is a real outstanding exposure and worth a task if the CTO wants it closed rather than watched.
2. Server close() is still not idempotent (it calls store.close() and server.close() unconditionally; a second call throws). The closedByTest flag exists solely to work around that, and it is a correctness tripwire for anyone who later adds a second close path. Parked per §2, restated here so it is on the record.
3. Deliberate non-shortening of the bound: FRAME_MS stays 5000, so a fully red stream.test.js takes ~60 s to go red. That is inside AC-1's 120 s but it is 60 s of CI time on every red run. I did not tune it (the plan's §5.6 reasoning is explicit and I am not redesigning), but if CI wall clock ever matters more than flake margin, connectMs is now a per-call option and a red-path-only shorter bound is a one-line change.
