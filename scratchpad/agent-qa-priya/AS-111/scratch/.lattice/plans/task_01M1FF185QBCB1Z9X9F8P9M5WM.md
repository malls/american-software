# AS-57: invoicing: dependency-policy closed-world scan — residual blind spots found in AS-53 review

Filed from the AS-53 QA review (qa-priya). AS-53 closed the manifest-shaped blind spot (Dockerfile / compose.yaml / package.json are now scanned) and PASSES its own criteria; these are the residual gaps found by adversarial probing that are NOT stated AS-53 criteria. Each was confirmed by planting an unsanctioned `fetch('https://example.invalid/')` in the AS-53 worktree and running the suite in-image (`docker compose -p asc-invoicing-qa53 ... run --rm --build test`): the suite stayed 68/68 green in every case. All three are "silent" (no test fires); item 4 is the opposite class (a loud false positive) and is here only because the fix is adjacent.

1. Closed world is closed over the IMAGE, not the host directory. The Dockerfile copies an explicit top-level list (package.json package-lock.json app.js server.js lib routes views public test compose.yaml Dockerfile .dockerignore + tokens.css->vendor/). A NEW top-level file — e.g. `apps/invoicing/compose.override.yaml` (which compose auto-merges into the running stack) — never reaches /app, so `classifyTree` never sees it, test #3 cannot flag it as unknown, and an outbound healthcheck inside it is invisible. Reproducer: create `compose.override.yaml` with `services: web: healthcheck: test: ["CMD","node","-e","fetch('https://example.invalid/')"]` -> 68/68. The AS-53 plan §2.1/§2.4 wording ("scanned the moment it appears", "visible two-line change") holds only for files under an already-COPY'd directory. Decide: (a) COPY the whole app dir (relying on .dockerignore) so the world is the directory, or (b) keep the explicit list and document that top-level additions must be added to the Dockerfile COPY (deploy-shape.test.js pins those lines, so (b) is already partly enforced by convention — but it is enforced only if someone remembers).

2. SKIPPED_DIRS (node_modules, test, vendor) are matched by entry NAME at every depth, so `lib/vendor/probe.js`, `lib/test/probe.js`, `routes/node_modules/x.js` are walked past silently. Reproducer: `lib/vendor/probe.js` containing `fetch('https://example.invalid/')` -> 68/68. Pre-existing before AS-53 (the plan said "exactly as today"). Fix: skip those names only at the top level of APP_DIR (a depth check in classifyTree), and add a test-#3 style assertion that no nested skip-named directory exists.

3. `stripHashComments(text, {trailing:true})` (and its origin, `stripComment` in test/deploy-shape.test.js, which it duplicates verbatim) has no backslash-escape handling. In a YAML double-quoted scalar, `\"` is an escaped quote; the stripper treats it as the closing quote, so a following ` #` is taken as a comment and the rest of the line — still inside the string — is stripped. Reproducer: `container_name: "asc-inv \" # fetch('https://example.invalid/')"` in compose.yaml services.web -> 68/68, and the running compose stack accepts the file (the value is a legal string). Adversarial-only (nobody writes this by accident), but it violates the stated intent "never inside quotes". Fix in both files, or extract the shared helper (AS-53 plan §11 Q2 proposed the shared-helper follow-up).

4. (nuisance class, not a blind spot) `.DS_Store` is in neither repo-root `.dockerignore` nor `.gitignore`. A Finder-created `.DS_Store` anywhere under apps/invoicing is COPY'd into the image and fails test #3 loudly ("neither app source, a manifest, nor listed in UNSCANNED"). Loud is the correct failure mode, but a macOS developer will hit it. Fix: add `**/.DS_Store` to `.dockerignore` (deploy-shape.test.js pins that file — update its expectation in the same change) and `.DS_Store` to `.gitignore`. Observed by developer-marcus in the AS-53 implementation report; recorded here so it is tracked.

Scope note: items 1 and 3 touch test/deploy-shape.test.js, which AS-53 §1.2 kept out of scope — that is why they are here and not in AS-53.
