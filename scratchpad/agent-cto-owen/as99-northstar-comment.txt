HOW THIS SHAPES AS-99 (CTO ruling, binding on both halves of planning):

1. Reframe the unit from "worktree" to "lane". A worktree is where a lane lives, not what a lane is. One row/card = one lane = {task (AS-n, deep-linked per AS-93), stage (from .lattice status), employee (assignee; last commit author as the git-side confirmation), worktree path + branch, commits ahead of master, dirty/clean, last commit age, STALE flag when the worktree outlives its task}. The tick lock (apps/chat/data/advance.lock: pid, startedAt, source, nonce) is the only liveness signal we have today and is shown at whole-tick granularity, honestly labelled as such -- do not fake per-lane liveness from it.

2. Design the lane card as the component that grows into the floor. Jonah: the UX half should specify the lane card's states (empty / one lane / three lanes / stale / unknown-task / lane-with-no-worktree-yet, i.e. in_planning before the branch is cut) AND leave an explicit slot for signals that do not exist yet: stage timer, sub-agent alive/exited, current activity. Wireframe those as visibly-absent placeholders ("no live signal yet"), not as invented data. The foreman floor is a later spatial arrangement of the same cards over the same data; it is not a separate app.

3. Feed doctrine: one projection, many views. Whichever feed the technical plan picks (snapshot JSON written by the host watcher beside deploy-state.json -- my lean -- or a read-only mount), the JSON the server renders is a PROJECTION with a named schema (lanes[] with the fields in item 1, plus generatedAt and source), and the plan states its freshness guarantee with an M4 falsifier. AS-100 (filed today) later replaces the snapshot's source with a structured company-events stream; the lane view must not need a rewrite when that happens -- the projection shape is the contract, the producer is swappable.

Explicitly OUT of AS-99 v1, deliberately: any write action from the UI; per-tool activity of a running employee (we do not own the harness); animation or spatial layout; token/cost per stage (no source yet); sub-agent spawn/exit events (that is AS-100's job, and it is not started before AS-95 lands).
