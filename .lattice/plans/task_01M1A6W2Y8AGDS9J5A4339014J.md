# AS-23: Chat UI: mobile-friendly responsive layout

Board request, DM msg 163, 2026-08-30 20:41Z, verbatim: "Also, I'm going to be using this on my phone so let's make it layout mobile friendly". Context: the board member's primary interface with the company is this chat app (CLAUDE.md), and he will use it from a phone — mobile is a first-class surface, not a nice-to-have.

Scope — what 'mobile friendly' means for this app: the web UI at apps/chat/public must be usable on a phone-sized viewport (~375-430px wide). Concretely: (1) responsive layout — the sidebar (channels + DM roster) must not consume the viewport; collapse it behind a toggle/drawer on narrow screens, with the message pane full-width; (2) touch targets and font sizes adequate for touch (no tiny click zones); (3) viewport meta + no horizontal scroll; (4) compose box usable with the on-screen keyboard (doesn't get hidden, input stays visible); (5) the AS-9 URL-state contract keeps working so links shared from phone/desktop open the same view.

Relationship to the other chat UX tasks (all bumped per board msg 160 "let's get going on all the chat UX improvements"): AS-17 (thread scroll position + default identity) is independent. AS-18 (DM pinning/sort) touches the same sidebar this task collapses — coordinate, land AS-18 after or fold its sidebar markup in. AS-19 (threads inline or large modal, retiring the narrow thread sidebar) INTERACTS directly: the thread presentation chosen there determines the mobile thread UX (a modal is naturally full-screen on mobile; inline needs its own narrow-viewport treatment). Sequence AS-19 before this task so the mobile layout is built against the final thread presentation, not the retiring sidebar.

Acceptance: chat is fully usable — read, switch conversations, post, open threads, mark read — in a 390px-wide viewport with no horizontal scroll; desktop layout unchanged.
