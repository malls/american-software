# AS-7: Message-triggered /advance: chat app becomes the investor's primary interface

Decision (Forrest, 2026-08-30, recorded in CLAUDE.md Operating Modes): sending a message in the chat app should trigger one /advance tick when no agent loop is already running. Goal: the chat app becomes Forrest's primary interface with the company; Claude Code chat recedes to governance/meta. Design constraints discovered so far: (1) The chat app runs only via docker compose (AS-4); a container cannot spawn a claude session on the host, so the trigger needs a HOST-SIDE watcher (launchd agent or supervised script) — keep it tiny. (2) Signal channel: compose bind-mounts ./data, so the server/store can touch a sentinel file (e.g. data/last-human-message) on insert of a message authored by human:* — the host watcher (fswatch or cheap polling) reacts to that; do NOT trigger on agent-authored messages. (3) Single-flight lock shared with the loop: if a /loop or a tick is already active, the watcher no-ops — the running tick's inbox pull delivers the message (suggested: a lockfile the watcher, /advance, and /loop-mode ticks all respect; document it in advance.md). (4) Debounce bursts (10-30s) so a rapid multi-message send fires one tick, not N. (5) Fire via headless invocation: claude -p '/advance' from the repo root; investigate permission-mode requirements for unattended runs and document what the host must have configured. Acceptance: with nothing running, a DM sent from the browser UI produces exactly one tick that reads the inbox and acts; with a loop running, no extra tick fires; agent-authored messages never trigger; watcher survives reboot (launchd) or documents how to start it.
