# AS-134: Board ask: enable Accounts v1 support on the test-mode Stripe account (Dashboard toggle) so Connect onboarding can start

WHAT. The board flips one free Dashboard setting on the SAME test-mode Stripe account AS-51 opened: "Accounts v1 support" (Settings -> Features, feat_accounts_v1_support). No new account, no signup, no spend. Alternatively the CTO decides the app moves to Accounts v2 (POST /v2/core/accounts) — a design change with its own task; this ask is the plan-preserving path.

WHY. AS-50 phase 1 (2026-09-12) stopped at the driver-side Connect start: POST /connect-stripe/start answered 502. The app's first Stripe call, the bare POST /v1/accounts that lib/connect/onboarding.js makes (params {} on purpose — the Standard-equivalent controller defaults; the custody guard bans controller[...]), is refused by Stripe with 400 invalid_request_error: "Stripe no longer recommends Accounts v1 for new Connect integrations. Create connected accounts with POST /v2/core/accounts instead ... If your integration requires v1 account creation for a supported compatibility scenario, enable Accounts v1 support in the Dashboard: https://dashboard.stripe.com/settings/features/feat_accounts_v1_support". Replayed from the host with the same key, Stripe-Version 2026-08-26.dahlia and an empty body — same 400 (request id req_lEJA1UlCpOyy8b); the key itself works (GET /v1/account 200, acct_1UEt5BE6PyFsj8A8, US). This is not the plan's return_url contingency (that would be /v1/account_links failing after /v1/accounts succeeded; here no account row exists) and not a transport problem.

DECISION CONTEXT. The stateful double (AS-49) and stripe-mock both accept the bare v1 create, so nothing in the suite could have caught it; it is exactly the kind of divergence AS-50 exists to find. Until the toggle is on (or the app is moved to v2), no freelancer can start onboarding, so gate A cannot be reached. Everything else in phase 1 was observed working for real: stripe listen Ready under the same account (API version 2026-08-26.dahlia, STRIPE_API_KEY honoured from the env), the relay on 127.0.0.1:8352, web up with both secrets [redacted] on the boot line and /healthz, signup 303 -> /, dashboard 200 S3-EMPTY-FIRSTRUN.
