Screen 2 — Connect Stripe

Route (provisional): GET /connect-stripe, plus two Stripe redirect targets, /connect-stripe/return and /connect-stripe/refresh, which resolve into this same screen's states rather than rendering pages of their own (01-screens.md §2). S2-DEFAULT-NOTSTARTED Default Signed in, connected account never created

Connect your Stripe account

You'll be taken to Stripe to verify your identity and add payout details. We never hold or move your clients' money — Stripe pays you directly.

S2-RETURN-READY Default Stripe return redirect; requirements met, account can charge

You're connected

Your Stripe account is ready to accept payments.

Continue to Dashboard

S2-LOADING Loading Between clicking "Connect" (or the refresh handler firing) and Stripe's redirect — no form to fill, so this is brief and label-only

Redirecting to Stripe…

No fields render in this state — there is nothing to fill in while control hands off to Stripe.

S2-ERROR-SYSTEM Error — system Our call to create the account link fails, before any redirect happens

Couldn't reach Stripe

Something went wrong starting Stripe setup. You haven't left this page — try again.

S2-RETURN-NOTREADY Permission-denied / gated Stripe return redirect; requirements still outstanding (C-11) — the state that gates invoicing everywhere else in the product

Almost there — Stripe needs more information

Stripe still needs more information before you can accept payments. You can't send invoices until this is finished.

This is the only state that blocks invoicing (00-flows.md Flow 5); it does not block contract creation, which has no Stripe dependency.

S2-DENIED-SIGNEDOUT Permission-denied / gated No session

No form renders

A request for this screen with no valid session is redirected to Screen 1, sign-in mode, with a one-line reason ("Sign in to continue") — 00-flows.md Flow 4. On success, the freelancer returns here rather than landing unconditionally on the Dashboard.

S2-REFRESH Abandonment Stripe invalidates the onboarding link before completion (Stripe's own timeout, not a freelancer action) — Stripe redirects here, to the refresh URL, not the return URL

Refreshing your setup link

Transient: this handler mints a fresh account link and immediately redirects back into Stripe's flow — a freelancer sees S2-LOADING for a moment, not this page's own content. If minting the fresh link fails, that is S2-ERROR-SYSTEM, not a new state.

S2-ABANDON Abandonment Freelancer closes the tab mid-Stripe-KYC, later returns directly (not via a Stripe redirect)

Nothing changed on our side

Renders S2-DEFAULT-NOTSTARTED again — we were never told anything changed, because Stripe never redirected back to us. Stripe holds whatever partial progress the freelancer made on their own KYC flow; clicking "Connect with Stripe" again resumes them where Stripe left off. That is Stripe's behavior, not something this product controls or can surface.
