How to use this page

Every color, size, and rule below is a named CSS custom property in ../tokens/tokens.css (also mirrored in ../tokens/tokens.json). If a color, spacing value, or font isn't here, it isn't part of the brand yet — see BRANDING.md §0 and §9. This page opens directly from file://: no server, no build step, no network request, no JavaScript required for correctness (the theme toggle above is a progressive enhancement — the page already renders correctly from prefers-color-scheme with JS disabled).

Both color schemes are shown side by side throughout this page in labeled panels, so you can review light and dark without changing your OS setting. The "Toggle theme" button above additionally forces the whole page (including the page chrome) into light or dark, for whole-page inspection.

Typeface note (BRANDING.md F1): this repository ships no font binaries and no @font-face rule (§7.D.14 forbids binary assets; §4.1 requires self-hosting if they ever do ship — the two haven't been reconciled yet, so v1 ships fallback-only). Every typographic sample on this page is rendering on the fallback stack (-apple-system / system-ui equivalents), not on Inter or JetBrains Mono, unless your system happens to have those installed. Contrast matrix (generated)

BRANDING.md §3.4 verifies every color mostly against bg-canvas. Real components also sit on bg-surface and bg-surface-sunken, so this table is the full foreground × background × mode cross-product, computed mechanically by tokens.test.mjs from the same token hexes tokens.css ships (WCAG 2.1 formula, BRANDING.md §11). Failing combinations are rendered here anyway, honestly labeled — hiding a known failure would be worse (BRANDING.md's own rule: "change the value, don't change the claim").

12 combinations fail, all in dark mode, all involving a solid fill (accent-solid/-hover, danger-solid/-hover, focus-ring) or error text against bg-surface-sunken. Three were already named in the CTO's acceptance read (F2); the other nine — mostly hover-state fills — surfaced only once the check stopped being one person manually sampling pairs. This is exactly what the generated matrix is for. None of these are fixed in this task (palette amendments are a v1.1 brand-doc call, not an AS-29 prerequisite); see this task's Lattice comment for the full account.

The brand never does this (BRANDING.md §7)

Reproduced here as a build-time checklist — full rationale for each rule is in BRANDING.md §7.

  • No flags, stars-and-stripes motifs, eagles, bunting, fireworks, or literal patriotic iconography
  • No red/ink/blue composed in a flag-like arrangement, even incidentally
  • No stock photography, mascots, or "diverse team" imagery
  • No gradients, glassmorphism, neumorphism, or decorative surface trends
  • No decorative drop shadows, glows, or multi-layer "soft UI" shadows
  • No typeface beyond Inter and JetBrains Mono without a written amendment
  • No Inter weight below 400 or above 700 in running use
  • No text below its documented AA ratio outside the two exempt/decorative tokens
  • No hype copywriting (revolutionary, seamless, best-in-class, ...)
  • No fully-rounded treatment on standard buttons, cards, or containers
  • No emoji as functional UI iconography
  • No dark patterns — disguised opt-outs, fake urgency, pre-checked add-ons
  • No licensed or paid typefaces, icon sets, illustrations, or tooling
  • No binary or externally-hosted design assets in this repository
  • No animated or video logo treatment in v1
  • No product name, iconography, or product-specific visual metaphor here
